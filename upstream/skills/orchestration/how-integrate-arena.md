# Candidate and review integration policy

## Preserved procedures

Arena keeps task framing, a private rubric, independent candidates, a cross-family judge, criterion-based selection, coherent grafting, and verification. Architect uses that mechanism for structurally distinct sketches, retains all three design references, and preserves its optional checkpoint and re-grounding loop. Interrogate uses the runner mechanism but keeps every reproduced defect, not a winning candidate. Blast-radius keeps its original procedure and wide-change arena escalation unchanged.

## Execution and model policy

The coordinator reads the shared Markdown preferences through arena. Preserve the configured initial seats and their order. Retain upstream expansion for more design directions by cycling through configured entries, stating the expanded count without inventing models. Explicit aliases inherit the parent; otherwise use declared provider/model/options. Unavailable choices require user resolution. The cross-judge must come from another actual model family; provider IDs alone do not establish diversity. Preflight judge eligibility before candidate dispatch only for invocations that include Phase C. Interrogate skips Phase C and does not need a judge check or judge-related confirmation. If no eligible judge runs, preserve upstream's omission-and-report path and let the parent choose the base. Unknown family is disclosed, not invented. An explicit task requirement for a judge still remains an unmet requirement. No extra reduced-review approval is inserted. T3 continues to prohibit substituting unavailable requested models without authorization.

Use T3 dispatch and host-owned checkouts. Independent artifact directories live under workspace-local `.agents/cache/`; accepted durable material goes to the agreed destination. Candidate and judge tasks carry absolute file pointers and their specific role. Children do not dispatch more agents. Judges inspect completed candidates read-only; any check that may write runs in their own scratch copy. Runners do not receive the rubric, while the coordinator and judge do. Unavailable targets are reported without unasked substitution. Preserve upstream dropout handling for missing candidate outputs; do not insert a new approval solely because fewer candidates returned.

A T3-managed worktree starts from the parent commit and excludes uncommitted changes. The coordinator captures staged and unstaged binary Git patches, scoped untracked and relevant ignored payloads, and a manifest of base SHA plus index/worktree hashes, file kinds, modes, and deletions. Children apply this bundle inside their already host-created checkout and compare both states before probing. Include rename source/destination paths and relevant ignored grounding sketches; exclude unrelated ignored files, secrets, and the bundle itself. Recheck capture stability before dispatch. This is ordinary file input delivery, not an assumed T3 transfer API. If bundle access or verified replay fails, the slice is blocked; a clean committed baseline is not a substitute for the requested review. Do not create child checkouts in shell commands, or commit/push merely to make dispatch possible without task authorization.

## Semantic upstream updates

Review old source, new source, current output, and these reasons together. Directly retain new reasoning or reference improvements when compatible. Adapt changes to model selection, isolation, waiting, or input transfer through the current T3 host rules. Reconsider this policy when upstream changes candidate independence, rubric visibility, cross-judge eligibility, synthesis, verification proof, retries, or human checkpoints. Ask the user when a delta changes agreed review depth or execution scope. Passing exact replacement checks is not semantic approval.

## Verification limits

Source, license, dependency, and generation checks establish the declared artifact. Synthetic scenarios evaluate instruction decisions only. A scoped live interrogate fixture now verifies T3-managed checkout input replay across Codex and Opus, including tamper rejection and child-local defect reproduction. Full panel/coordinator workflows, cancellation, and application design/review runs still require separate evidence. The [input-bundle exercise](../../../evals/input-bundle.md) demonstrates Git replay in disposable local fixtures; it does not prove T3 checkout access or dispatch. No new scheduler, worktree manager, or runtime input-transfer framework is introduced here.

The [live input-replay record](../../../evals/interrogate-live.md) distinguishes actual host transfer from the earlier disposable Git exercise. The live case uses an empty committed baseline and staged additions plus unstaged changes; it does not claim committed-file rename coverage or arbitrary filesystem metadata.


## Installed companion resolution

The T3 translation carries companion-resolution rules inline: named skills resolve to sibling ../<name>/SKILL.md files in the same distribution, short principle names normalize to principle-<name>, relative references resolve from their containing file, and children receive absolute paths plus these rules. Installed skills do not require a repository-root README, which per-skill installers do not copy. This corrects the local host translation rather than changing upstream procedure; no new Patch/Design policy or dependency resolver is introduced. Mixed-source namesakes and partial installations still have no automatic closure guarantee.
