# Audit-trail integration policy

Preserve one canonical six-column TSV decision log, append-only correction, evidence pointers, logical run ownership, audit against the actual transcript, mandatory cross-family review, and the source Attention output. Do not substitute a persuasive summary for a trace or self-review for another model family.

Copy scripts/log.sh and the header template unchanged from the pin. The generator preserves the script's executable mode and checks execution-bit drift as well as bytes. Invocation resolves the helper from the distributed skill directory by absolute path, not an unrelated project script. The existing sanitizer, timestamp, header, and append behavior remain the source implementation.

Use the user-directed workspace-local storage convention for operational/resumable logs and requested durable review copies. The upstream rule for committing a trail when a reviewer needs it remains subject to task authorization; adopting the skill does not commit anything. Storage adaptation does not change the canonical format or rewrite history.

Read actual scoped T3 thread activity, including pagination and truncated text, instead of Cursor JSONL paths. Logical run identity survives later turns and summaries; a host turn/runId is not automatically a new conversation. Preserve the source start-row ownership boundaries. Missing activity/evidence is an incomplete audit rather than an invented successful trace. Do not poll a live delegate thread for audit evidence.

The parent directly selects and dispatches the required reviewer on a different actual model family. Shared models.md supplies per-job option policy, not another workflow's model choice. Give the log, actual scoped activity, and companion paths explicitly. The child inspects its assigned trail without recursion or source edits. The actual reviewer and flags must support the Attention output; a synthetic component evaluation is not a live cross-family verdict.

For an A-to-B update, inspect the entrypoint, header, and executable helper together. Retain changes to escaping, append semantics, run ownership, evidence scope, or review independently of host paths. Mode-only upstream changes remain visible in the lock and generated checks. New workflow decisions require user discussion; upstream-intent Patch corrections are implemented and reported with retirement criteria.

The real generated helper is exercised for sanitization, UTC timestamps, six-column output, append-only history, argument errors, and preserved executable behavior. Full T3 history traversal, live cross-family trail review, multi-run concurrency, and real commit/publication remain separate checks. See the [evaluation](../../../evals/show-me-your-work.md) and [verification record](../../../docs/verification.md).
