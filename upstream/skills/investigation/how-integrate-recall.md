# Recall integration policy

Preserve the two evidence records: scoped personal work history and shared evidence through why. Keep the real time window, topic/project boundaries, current-chat exclusion, per-thread schema, live artifact verification, and tight output. A supplied state capsule still skips unnecessary history mining.

Replace Cursor JSONL storage assumptions with the current project's T3 thread APIs. Enumerate pages to cover the window; search is non-exhaustive. Read the relevant thread before citing it. Follow both item pagination and text truncation offsets, and use activity when execution evidence matters. Return actual thread links. Missing history or activity is an explicit gap. Unconfirmed list filter defaults, unknown ordering, and capped run metadata cannot establish complete coverage. Use last-activity timestamps, finish enumeration when ordering is unknown, and do not read active delegate threads as polling. Reading completed child results can mark delivery; respect that ownership effect. Never search other projects or machines merely to fill a missing result.

The parent directly dispatches parallel history miners under current T3 rules, preserving upstream's fast/cheap model criterion. Choose an available model and settings appropriate for responsive, low-cost extraction; respect explicit task choices. Missing catalog price/latency metadata does not itself require a question: choose an efficient/small model or routine-work effort as a disclosed heuristic, without claiming measured cost or latency. Apply the shared per-job option rules to that independently selected model, not another workflow's model choice. Do not borrow another workflow's default model or replace model selection with implicit parent inheritance. No additional coordination skill is a prerequisite. For one or two chats, retain upstream's direct-read path. The parent owns scope and thread selection; miners read their assigned records without further delegation. Shared-record investigation retains why's access and citation rules. Neither adoption nor an empty history result grants access to unrelated connected sources.

Unavailable session-pickup and automate-me routes are named as limitations, not silently substituted. Recall does not implement a miniature named-thread pickup in place of the unadopted playbook. The original output-status vocabulary is preserved. Report missing verification as an evidence gap without inventing a status or claiming the full procedure completed. Both the added status label and the prior shared-worker model policy are withdrawn.

For an upstream update, compare old and new history selection, privacy, evidence, and output rules against this policy and the current integration. Retain compatible reasoning improvements directly; adapt changed host APIs deliberately. Preserve upstream mining/model-selection decisions instead of introducing a dependency merely to reuse orchestration. Reconsider scope changes or new automatic history sources with the user. Exact replacement success does not establish semantic compatibility.

A narrow live API probe confirmed current-project enumeration and paginated activity access in this workspace, reading one item of the already active conversation. It did not mine unrelated history or establish exhaustive cross-thread recall, worker execution, or the full shared-record sweep. Worker access, multi-page traversal, and filter defaults were not validated. Those remain separate evaluation work.
