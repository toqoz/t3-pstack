# Personal mode adoption

Automate-me retains the upstream flow: discover/update the existing personal mode, mine recent history in parallel time slices, ask the user, cluster evidence, author, refine prose, and deliver through a worktree/PR. This is T3 adaptation, not a new personal-style policy. No personal mode was generated or installed by this adoption.

## History boundary

The user selected T3-managed Codex/Claude history in the same project. Use the common T3 project/thread API across providers, including related terminal delegated descendants. Do not scan standalone Codex CLI/Claude Code transcript stores or other projects. No recall or reflect invocation is added as a dependency; mining remains the original inline pass.

Include inactive conversation and fork-local activity plus terminal delegated work, including failures, interruptions, cancellations, and rollbacks, with an explicit cutoff for the caller's current context. Preserve project/parent relationships, provider/model, item identity, authorship, timestamps where available, pagination coverage, and missing evidence. Child kickoffs can be agent-authored user-role messages. Copied briefs, returned results, and provider duplicates must not create independent evidence of human preferences. Preserve the original repeated-pattern/cross-slice checks and direct user interview.

T3 0.1.7's installed source confirms omitted settled/snoozed filters do not exclude those threads. Its list API identifies provider and subagent lineage. Actual completed Codex and Claude child activity was paged and exported as a component probe: 12 non-reasoning items across 2 activity pages for Codex and 23 across 4 pages for Claude, including 6/11 command events. Truncated text was followed through offsets. Each included one agent-authored kickoff labeled user_message. This is protocol/access evidence, not a full recent-history mining run.

## Other host mappings

Replace .cursor/skills with .agents/skills. Use the host's available authoring skill rather than inventing Cursor create-skill. Preserve YAML validity, user-chosen invocation intent, subjective draft iteration, existing-skill-first updates, and no-overfitting rules. Automatic registration remains host-dependent.

Use host questions; if multi-select is unavailable, keep the short choices and accept several in text rather than send an unsupported field. The mode is a granularity reference, not a workflow to run or a set of preferences to copy. No miner role is defined: the caller model/effort is the starting point for the source-referenced job adjustments. Explicit inheritance aliases and fixed task settings keep their defined precedence; no other workflow model is borrowed.

Delivery uses T3-managed worktrees and the actual canonical repository for the approved destination, respecting uncommitted-input and authorization boundaries. No commit, PR, global skill/config edit, or standalone CLI log access occurred during adoption.

## Review corrections

The parent enumerates and partitions source pointers, not the full raw history in its context. Each miner reads its own slice; supported per-slice exports are an alternative when needed, without inventing an export capability. Working-artifact locations follow the host/task conventions rather than a new hardcoded personal storage rule.

Validate returned project identities. Human-created forks are conversations in their own right for their local items, while inherited/copy items retain their canonical source identity. Failed/interrupted conversation states do not erase user corrections. Canonical statements/events are counted once across observations, threads, and slice boundaries; time slicing alone cannot establish independent recurrence. Genuine distinct human instances remain evidence for the original interview and confidence judgment.

T3 0.1.7's extracted direct-child ownership guard selects only the reader's own direct child for terminal-result acknowledgement. An unrelated mining reader does not consume another parent's result. This was verified from installed source and four pure-helper cases, not a live notification test. Own-child reads may acknowledge delivery; do not generalize this into side-effect-free reads on other host versions without checking the contract.
