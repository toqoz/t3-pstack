Read every reviewer template and retain its untrusted-transcript boundary.

Report pending rows separately from applied, rejected, or Backlog work.

## Terminal-child evidence correction

The first T3 translation restricted collection to the parent alone. The user requested including related child logs. Collect actual terminal-child messages and command/tool activity, not only summary notifications. Preserve provider/model, thread/item identity, lineage, cutoff, and coverage in the collated evidence. Deduplicate copied briefs/results and distinguish human instructions from agent-authored child kickoff messages. Require actual skill-read/invocation evidence; do not equate a named assignment with use.

T3 project enumeration exposes provider identities and subagent relationships. Actual completed Codex and Claude child activity is available through the same API. This does not establish access to arbitrary standalone CLI sessions or every native-provider subagent body. Such absent data must be reported, not silently represented as complete coverage.


## Delivery semantics and review corrections

Validate every listed/read thread's projectId against the authorized scope. Terminal means ended, not successful: failed, interrupted, cancelled, and rolled-back histories can contain the essential learning. This corrects an unintended success-only narrowing; no new Design policy was intended.

The installed T3 0.1.7 readThread code loads the caller and applies directAppOwnedChildTasks before acknowledging a terminal result. That guard requires the target to be a direct subagent of this caller. The unmodified extracted helper passed own-child, other-parent child, grandchild, and human-fork cases. Another conversation's child is not selected for acknowledgement. A read of the caller's own direct-child final result can acknowledge delivery and must not be described as globally side-effect-free. This is source/helper evidence, not a live notification-delivery test.


## Installed companion resolution

The T3 translation carries companion-resolution rules inline: named skills resolve to sibling ../<name>/SKILL.md files in the same distribution, short principle names normalize to principle-<name>, relative references resolve from their containing file, and children receive absolute paths plus these rules. Installed skills do not require a repository-root README, which per-skill installers do not copy. This corrects the local host translation rather than changing upstream procedure; no new Patch/Design policy or dependency resolver is introduced. Mixed-source namesakes and partial installations still have no automatic closure guarantee.
