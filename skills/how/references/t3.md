# T3 execution adapter

Use this adapter for every role in this skill. Pass it, the filled-in role template, the user's question, file pointers, and the relevant findings to each child. Children receive no parent history by default.

Dispatch and Result ownership are coordinator-only sections. Children perform their assigned role themselves and do not dispatch further agents.

Resolve `references/...` paths from the directory containing the skill's `SKILL.md`, including when a role template mentions another reference. Give children absolute file pointers so their working directory does not change which file they read.

## Dispatch and model selection

Follow the host's current T3 orchestration instructions. Use native subagents only for an offered model on the current provider with no settings beyond the parent and no isolation/background requirement. Use `delegate_task` for a different provider, explicit settings, isolated checkout, or background work. Before the first delegation, read `orchestrator_capabilities` once to resolve providers, models, and valid options. Put requested options in `target.options`.

Preserve the skill's role separation and independent passes. A simple how question still gets an explainer; complex questions still get focused explorers followed by a separate explainer. Why still gets investigators for available evidence categories and a separate synthesizer.

Read `references/models.md` and the user's Markdown preferences at the path it defines before dispatch. An explicit model request for the current task takes precedence, then a saved role choice, then the shared default. Resolve each role's provider, model, and options against the live T3 catalog. Resolve the starting effort from saved role preferences/budget, then apply the job-based effort and speed rules in references/models.md. A current task's explicit fixed settings take precedence; saved role efforts are starting levels. The how roles are `how explorer` and `how explainer`; the why roles are `why investigators` and `why synthesizer`. A missing configuration uses the Codex/Opus defaults, not implicit parent inheritance. Only the explicit aliases `inherit-parent` and `auto` omit the target. Never invent model IDs or switch unavailable models/providers without a choice. Map budget/job-derived effort to supported same-model options under the shared rules and disclose rounding; that alone needs no extra confirmation. An unsupported exact current-task option or a rejected final target requires a choice, not silent substitution. Distinct contexts on one model are not model diversity.

For delegates, retain the task ID and follow the returned `next`. Do not poll, sleep, or schedule a watcher while waiting for a delegate. Use the host's native wait behavior for native children. Cancel a delegate you abandon or replace with `task_cancel`. A reviewer re-check is a new task.

## Investigation boundaries

These workflows inspect code and evidence. They do not edit source, commit, send messages, or mutate external services. Investigators and synthesizers that need connectors must not run in a mode that removes those connectors. Express the investigation boundary in the task and verify tool availability rather than assuming a host's Ask or read-only mode preserves access. Do not create shell worktrees for investigations.

Use the current environment's file-read, search, and connected-source tools. Names such as Read, Grep, Glob, and source-specific MCP calls in upstream templates describe capabilities or examples, not guaranteed tool names. Discover the actual tools and inspect their schemas. Do not assume any connector, table, organization, or authentication exists. Report missing access as a gap. Do not install or connect services as part of an investigation.

Discover only sources relevant to the user's question. Do not treat an unrelated connected account as permission to search its private contents. Respect the host's communication, permission, citation, and source-access rules.

## Result ownership

The parent checks the evidence and owns the final answer, following the upstream Present step. Preserve the explainer's substance and the synthesizer's confidence language. Flag unresolved contradictions in an annotation or request a fresh correction pass rather than silently rewriting the report. A child report is evidence to inspect, not proof of correctness. If a required role cannot run, report the incomplete workflow rather than claiming the full procedure ran.
