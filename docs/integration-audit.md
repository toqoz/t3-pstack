# Integration scope audit

The target is T3 adaptation, removable upstream-intent patches, and explicit design proposals worth reconsidering. Implementation convenience alone does not justify adding a workflow dependency or changing model policy.

## Removed accidental reuse

- **recall:** The added swarm dependency imported its worker model policy. Restore direct mining and upstream's fast/cheap criterion; this was corrected before this audit.
- **reflect:** The added arena reference only borrowed dispatch/completion. Remove it and dispatch the original three roles directly, retaining their own configured models and separate synthesis.
- **no-comments:** The added arena reference borrowed dispatch and isolation instructions for a single reviewer. Remove it; the parent directly dispatches the reviewer against stable accessible inputs. Keep the reviewed documentation/design policy and original how/why/architect relationships.
- **setup-pstack:** Remove the investigation adapter reference. Its no-edit boundary belongs to how/why, while setup must save approved preferences through its own validation/write procedure. Retain shared model defaults.

Architect and interrogate already use arena upstream. Teach already uses how/why. Recall already uses why. These are original workflow relationships and remain intact.

## Design decisions after user review

The user chose upstream behavior whenever there was no specific, useful design direction. Arena's extra reduced-review approval, the alternate sequencing baseline, reflect's local-first Backlog, and recall's added status tag are withdrawn. The only remaining Design changes are the explicitly discussed no-comments merge and teach's requested-language policy.

- **arena:** Preserve upstream best-effort judging and candidate dropout reporting. Host rules still prohibit unasked provider/model substitution; this does not imply a new approval merely to skip an optional judge.
- **principle-sequence-verifiable-units:** Adopt the source unchanged, including clean-trunk rebase and the real-baseline purpose. Host authorization and ownership remain prerequisites, without inserting an alternate baseline policy.
- **reflect:** Preserve external Backlog delivery to the established project/team tracker. Selecting the actual destination and applying external-write/publication authorization are separate from the skill's Accepted-edit approval. Do not use a durable local proposal as the default destination.
- **recall:** Preserve the original state-tag vocabulary. Verification gaps remain explicit without adding a new tag or claiming an unsupported state.
- **teach / no-comments:** Retain only their already approved language and documentation-quality changes. New Design work must be discussed before implementation.

## Restored effort and speed policy

Upstream poteto-mode's Subagents section, explicitly referenced by the workflow dispatch instructions, treats configured effort as a starting level. It raises effort for hard work, lowers it for routine work, and normally uses standard speed unless urgent (with a separate verification exception). Current T3 instructions resolve role/budget options but do not preserve that job-based adjustment explicitly. This is not evidence that fixed xhigh is needed, and it is not a host requirement.

The user confirmed restoration of upstream's starting-level interpretation. models.md now retains the job-based effort/speed policy, the verification exception, current-task exact-setting precedence, supported same-model rounding, and T3 dispatch boundaries. No new speed default or personal configuration was written. See the [model policy](../upstream/skills/orchestration/how-integrate-model-policy.md).

## Additional independent-audit corrections

- Judge preflight runs only for invocations that include arena Phase C; interrogate does not need a judge it never uses.
- Recall makes a disclosed efficiency choice without blocking merely because catalog pricing/latency metadata is absent. It no longer substitutes a small direct-reading procedure for the unadopted session-pickup playbook. Its original output status tags are restored, with evidence gaps reported without invented status.
- Teach preserves progressive drawing with supported SVG/HTML if image generation is unavailable, while honoring a user-required specific medium. Tool availability is host-dependent; the audit's broad claim that T3 generally lacks image generation is not treated as an established fact.
- Setup restores same-model budget-derived rounding shown in its existing full proposal. Exact unsupported task settings remain a choice.
- Sequencing is now entirely unchanged upstream; its alternate working-state baseline is withdrawn.
- Benchmark retains all four observation categories and records unavailable evidence rather than quietly narrowing the requirement.
- Reflect uses upstream external Backlog delivery. Known authorization is reused; unknown destination/publication requirements are resolved separately from Accepted skill edits. The local-first default and the added reduced-workflow approval gate are withdrawn.
- Workspace-local storage is identified as this integration's user convention, not a universal T3 API rule.

The independent review confirmed source-plus-transform fidelity and 44 passing tests before these corrections. Subsequent component/scenario evaluations assess the rewritten instructions, not full live workflows. The current state and outstanding Design choices are recorded in the [verification record](verification.md).
